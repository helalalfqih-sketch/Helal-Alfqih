## 2. فكرة الحركة (من الحالة الأولى إلى البانر)

قسم بارتفاع `sectionH` يحتوي صندوقاً تثبيتاً `sticky` بارتفاع `heroH` يُشكّل إطار البانر النهائي. كل عناصر الحالة الأولى تفيض من هذا الإطار للأسفل وتتلاشى بشكل سلس قبل ظهور البانر. الكرة عنصر واحد دائم ومستمر لا يُعاد تركيبه إطلاقاً.

```text
scroll 0                                  scroll pEnd (تحرير الـ sticky)
┌──────────────────────┐                 ┌──────────────────────┐
│ هوية المتجر          │                 │  بانر عروض حصرية     │
│      ⬤ كرة كبيرة     │   ──────────▶   │ نص 50% + زر   ⬤ كرة │
│ نص + زر استكشف      │                 │              مضغوطة  │
│ لوحة البحث الذكي     │                 └──────────────────────┘
│ شريط المزايا         │
└──────────────────────┘
```

## 3. الهندسة المحسوبة (`useStageGeometry`)

**الثوابت القياسية:**
- `HEADER_SM`: 58px / `HEADER_LG`: 66px
- `PROJECTION`: 0.872
- `IDENTITY_H`: 50px
- `GLOBE_GAP`: 4px
- `AI_H`: 134px
- `TRUST_H`: 74px
- `PANEL_GAP`: 8px
- `NAV_RESERVE`: 76px
- `TRAVEL`: 340px

**آلية القياس والتكيف:**
- يتم حساب القياسات حياً عبر `ResizeObserver` وحدث `resize` واستقرار متدرج عند أوقات (120ms, 400ms, 1200ms, 2500ms) لضمان استقرار الخطوط والبيانات والشريط العلوي.
- يُقرأ `stageTop` فقط عندما يكون موقع التمرير `scrollY < 4`.
- **المساحة المتاحة:** ارتفاع النافذة − أعلى المسرح − الهوية − الفجوات − لوحة الذكاء − شريط المزايا − حجز شريط التنقل السفلي.
- **قطر الكرة:** `base = min(vw, 520|660, max(230, available/PROJECTION, vw*0.81|0.72))` ثم `diameter = base * PROJECTION`.
- **الحالة النهائية:** `heroH = 202|214|340`، `compactDiameter = 162|172|292`، و `scaleEnd = compactDiameter / PROJECTION / base`.
- **المواقع التراكبية:** `xEnd = cw/2 − 21 − compactDiameter*0.58` (إزاحة يمين)، `yStart = globeCenterY`، `yEnd = heroH/2`.
- **ارتفاع القسم والنهاية:** `sectionH = stageH + TRAVEL`، و `pEnd = clamp((sectionH − heroH)/sectionH, 0.5, 0.94)` حتى تنتهي الحركة تماماً لحظة تحرّر الـ sticky.

## 4. تايم‑لاين التمرير

يستخدم `useScroll({ target: sectionRef, offset: ["start start","end start"] })` مع `useSpring(110, { damping: 24, mass: 0.9 })` لمنح الحركة إحساساً فيزيائياً بالوزن والاستجابة. جميع التوقيتات تقع على مدى `0.00` إلى `0.78` وتُعاد قياسها بضرب المعامل `k = pEnd / 0.78`.

| المدى (نسبة التمرير) | التأثير البصري |
|---|---|
| `0.06 → 0.22` | تلاشي عناصر الحالة الأولى (`opacity 1→0`)، النص ينزاح لأعلى `y -18px`، لوحتا الذكاء والمزايا تنزاحان `y +24px` |
| `0.10 → 0.72` | الكرة: انكماش وتغيير الموضع (`scale 1 → scaleEnd`) بنقطة وسطى عند `0.40`، الانزلاق الأفقي `x 0 → xEnd` والعمودي `y yStart → yEnd` |
| `0.30 → 0.66` | ظهور إطار البانر الضوئي (`opacity 0→1`) وتكبيره الخفيف (`scale 0.98→1`) |
| `0.38 → 0.68` | محتوى العروض الحصرية: ظهور التدريج (`opacity 0→1`) وانزلاق النص من اليسار لليمن (`x -24px → 0`) |

تعتمد التحديثات حصراً على تحويلات `transform` و `opacity` التي تعتمد تسريع بطاقات الشاشة GPU بدون إعادة ترتيب للعناصر (`reflow`) أو تحديث حالة React مستمر (`setState`) أثناء التمرير، باستثناء مفتاح الوقاية البصري (`protectText` عند `p < 0.24k`).

## 5. محرك الكرة ثلاثية الأبعاد (WebGL & Canvas Rendering)

- **إدارة الكانفاس:** كانفاس واحد فقط مستمر في الصفحة كاملة، مع إيقاف حلقة الرسم تلقائياً عند إخفاء التبويب أو الابتعاد عبر `IntersectionObserver` هامش `200px`.
- **طبقات الرسم:**
  1. النواة الداكنة العميقة (Deep Central Core).
  2. شبكة الأسلاك العصبية الهولوجرافية (Holographic Wireframe Grid).
  3. نقاط البيانات الكروية (Fibonacci Lattice Cloud على `RADIUS * 0.995`).
  4. الغلاف الجوي والهالة الضوئية (Atmosphere Glow & Radial Gradient).
  5. ثلاث حلقات مدارية إضافية (Orbital Rings) بألوان البنفسجي، الأزرق والأزرق السماوي.
- **بلاطات المنتجات:** توزيع Fibonacci Lattice متوازن مع حزام قطبي، كل بلاطة موجّهة نحو الخارج بـ quaternion، وبقياس ثابت `TILE 0.74` ونسبة `4:5` مع تخفيت معتم حسب العمق الزمني Z.
- **منطقة عدم التداخل (Exclusion Zone):** تمنع ظهور أي بلاطة فوق عنوان الشاشة الرئيسي أثناء الحالة الأولى، وتلغى بعد الانكماش.
- **معالجة الصور والشبكة:** يستعين النظام بـ `use-loadable-products` للتحقق من سلامة روابط الصور، ويُحمّل الصور القادمة عبر وكيل الصور المحمول مع كاش للأنماط والنسيج يمنع أي وميض أو تأخير.

## 6. ميزانية الأداء والقياس المتكيف (Performance Budget)

| المستوى | dpr | عدد البلاطات | نقاط البيانات | المدارات / القطع | نبض الضوء |
|---|---|---|---|---|---|
| **low** | 1.0 | 18 | 1200 | 96 | متوقف |
| **mid** | 1.0 – 1.25 | 24 | 1800 | 128 | مفعل |
| **high** | 1.0 – 1.5 | 30 | 2800 | 192 | مفعل |

يتم تحديد المستوى تلقائياً بناءً على:
- توفر ودعم WebGL في المتصفح.
- عدد الأنوية المتاحة (`navigator.hardwareConcurrency`).
- ذاكرة الجهاز (`navigator.deviceMemory`).
- نوع الإدخال (`pointer: coarse` للهواتف الذكية).
- تفضيلات الحركة التقليلية (`prefers-reduced-motion`).

## 7. الحالات البديلة والتوافقية (Fallbacks)

- **تفادياً للحركة (`prefers-reduced-motion`):** تحول مباشر إلى تخطيط ثابت عمودي نقي (هوية المتجر ← كرة ثلاثية الأبعاد ساكنة ← نص العرض ← لوحة الذكاء ← شريط المزايا ← بانر العروض) دون أي ارتباط بحركة التمرير.
- **الشاشات الكبيرة (≥768px):** الاعتماد على `DesktopHero` بتركيبة عمودين متوازنة ومستقلة، مع الاحتفاظ بآلية الجوال متكاملة ومستقلة.
- **غياب تسريع WebGL:** تقديم بديل Canvas2D / HTML محسّن عالي الكفاءة يضمن ظهور المنتجات والكرة بدون أي خلل في تجربة المستخدم.

---

## 8. القواعد الذهبية للصيانة

1. **الاستمرارية:** كانفاس واحد فقط للصفحة، مع حظر إعادة تركيب الكانفاس أو إتلاف سياق WebGL أثناء التمرير والتنقل.
2. **عدم مضاعفة التحجيم:** صندوق الكانفاس أبعاده ثابتة بالبكسل، والتحجيم يتم على العنصر الأب فقط لتفادي تقليص صوان البكسلات مرتين.
3. **البيانات الحقيقية:** عدم استخدام بيانات وهمية؛ جميع المنتجات والأسعار والأسماء والصور تُجلب مباشرة من قاعدة البيانات.
4. **الانضباط البصري:** أي تعديل بصري يستوجب مطابقة `docs/design-reference/VISUAL_IMPLEMENTATION_CONTRACT.md` والمراجعة عبر أدوات الفحص الدقيق.
